## 1.6.0

### Breaking Changes

- `getPolicyPack` now takes a string `versionTag` input, for example `1.4.1`, the version shown in Pulumi Cloud. It replaces the integer `version` input. No working code needs migrating: the old input never worked, because Pulumi Cloud looks policy pack versions up by tag. [#1012](https://github.com/pulumi/pulumi-pulumiservice/issues/1012)
- `getPolicyPack`'s `policies` output is now a list of maps of any value, instead of a list of string maps, so each policy's nested `configSchema` object comes through intact. In Go, `LookupPolicyPackResultOutput.Policies()` now returns `pulumi.MapArrayOutput` instead of `pulumi.StringMapArrayOutput`. No working code needs migrating: `getPolicyPack` always failed in earlier releases. [#1207](https://github.com/pulumi/pulumi-pulumiservice/issues/1207)

### Improvements

- Added the preview `pulumiservice:api/agents:Definition` resource for managing Custom Agent definitions, including their agent role, integrations, instructions, approval mode, and paused state. An accompanying example creates a role, Custom Agent, and webhook automation that runs as the agent. [#1301](https://github.com/pulumi/pulumi-pulumiservice/pull/1301)
- Added an `expires` input to `AccessToken`, so a personal access token can expire. It takes an RFC 3339 date-time such as `2027-06-30T17:00:00Z`, like `OrgAccessToken`'s `expires`. Changing it replaces the token. [#1215](https://github.com/pulumi/pulumi-pulumiservice/issues/1215)
- Added `deployTags` and `tagFilters` to the `github` and `vcs` settings of `DeploymentSettings`, so a deployment can run when a matching git tag is pushed. Set `deployCommits` to `false` when you enable `deployTags`, because Pulumi Cloud rejects the two together [#1042](https://github.com/pulumi/pulumi-pulumiservice/issues/1042)
- Added an Import section to the docs of every `pulumiservice:index:*` resource, giving the ID format, a sample `pulumi import` command, and caveats such as secrets that can't be read back. `DeploymentSettings` and `Webhook` import docs now render as their own section instead of inline in the description. No behavior change. [#344](https://github.com/pulumi/pulumi-pulumiservice/issues/344)
- Documented that `Webhook` supports ESC environment webhooks, and which properties select an organization, stack or environment webhook. No behavior change. [#482](https://github.com/pulumi/pulumi-pulumiservice/issues/482)
- Documented that `Stack.forceDestroy` defaults to `false`. No behavior change. [#498](https://github.com/pulumi/pulumi-pulumiservice/issues/498)
- Documented that the `accessToken` provider config is optional and falls back to `PULUMI_ACCESS_TOKEN`, then to your `pulumi login` credentials. No behavior change. [#495](https://github.com/pulumi/pulumi-pulumiservice/issues/495)
- Clarified that `DeploymentSettings` `operationContext.oidc.gcp.projectId` takes the GCP project number, not the project ID, and how to look it up. No behavior change. [#491](https://github.com/pulumi/pulumi-pulumiservice/issues/491)
- Added `expires` and `roleId` inputs to `OrgAccessToken`. `expires` takes an RFC 3339 date-time such as `2027-06-30T17:00:00Z`. `roleId` assigns a custom role and is mutually exclusive with `admin: true`. [#1184](https://github.com/pulumi/pulumi-pulumiservice/issues/1184)
- Added the `buildRolePermissions` function, which builds a complete `OrganizationRole.permissions` tree from organization-level access and rules for stacks, environments, and cloud accounts (`InsightsAccount`), without writing the `__type` wire format by hand. This is the same model as the role editor in the Pulumi Cloud console. Each rule grants scopes on every entity of its type, on one specific entity, or on entities whose tags match. Tag conditions use the new `TagCondition` and `TagOperator` types (`equals`, `notEquals`, `exists`, `notExists`) and mean the same as in `buildStackMatchRule`. Each rule list accepts only scopes for its own entity type, so a scope can't be granted on the wrong kind of entity. The output of the other `build*Permissions` helpers can be folded in through `additionalEntries`. [#1161](https://github.com/pulumi/pulumi-pulumiservice/issues/1161)
- Added the `RbacOrganizationScope`, `RbacStackScope`, `RbacEnvironmentScope`, and `RbacAccountScope` enums, so `buildRolePermissions` scopes can be written as, for example, `RbacStackScope.StackRead` instead of `"stack:read"`. They are generated from the Pulumi Cloud scope catalog. [#1161](https://github.com/pulumi/pulumi-pulumiservice/issues/1161)
- Added the `getStack` function, which returns an existing stack's `stackId` and tags, for `buildRolePermissions` rules that select one stack by `id`. [#1161](https://github.com/pulumi/pulumi-pulumiservice/issues/1161)
- Deprecated `buildAllowPermissions`, `buildStackScopedPermissions`, `buildEnvironmentScopedPermissions`, and `buildInsightsAccountScopedPermissions`, which take scopes as untyped strings. Use `buildRolePermissions`, whose typed rules do the same thing: `organizationScopes` or an `all: true` rule in place of `buildAllowPermissions`, and a rule that sets `id` in place of the scoped helpers. If a scope you need isn't in the enums yet, upgrade the provider. The deprecated functions still work. [#1161](https://github.com/pulumi/pulumi-pulumiservice/issues/1161)
- Added a complete example to the `OrganizationRole` docs, and rewrote the `permissions` docs to lead with the helper functions. They also note that roles granting scopes directly open read-only in the Pulumi Cloud console's role editor. [#1161](https://github.com/pulumi/pulumi-pulumiservice/issues/1161)

### Bug Fixes

- Fixed refresh removing a webhook automation's `trigger.webhookSecret` from state. Pulumi Cloud returns this secret only when the automation is created; the provider now retains that create-time value across later reads. [#1301](https://github.com/pulumi/pulumi-pulumiservice/pull/1301)
- Fixed `OrganizationMember` failing to set or reset the `member` role in organizations that use the Reader, Builder and Maintainer roles, where Pulumi Cloud no longer lists a `member` role. The provider now uses the organization's default role instead.
- Fixed `getPolicyPack` always failing with `policy pack not found`, whether or not a version was given. It now requests versions by tag, and resolves the latest version from the organization's policy pack list. [#1012](https://github.com/pulumi/pulumi-pulumiservice/issues/1012)
- `Environment` no longer replaces the environment when `organization`, `project` or `name` changes only in case. Pulumi Cloud looks environments up case-insensitively, so the replace deleted the environment and its revision history to recreate the same one. Other replaces now create the new environment before deleting the old one, Pulumi's default order. [#1214](https://github.com/pulumi/pulumi-pulumiservice/pull/1214)
- Changing only the `config` of a policy pack on a `pulumiservice:index:PolicyGroup` now updates the pack in Pulumi Cloud. Previously `pulumi up` reported the update but sent nothing, so the pack kept its old config. [#1205](https://github.com/pulumi/pulumi-pulumiservice/issues/1205)
- On `pulumiservice:index:PolicyGroup`, removing a child account from `accounts` while its parent account is still listed is no longer reported as a change, because Pulumi Cloud keeps child accounts with their parent. Changing `organizationName` now replaces the group, as the docs say, instead of attempting an update. [#1205](https://github.com/pulumi/pulumi-pulumiservice/issues/1205)
- `Environment` refresh no longer removes the environment from state when Pulumi Cloud returns an error other than 404, such as an authentication or network error. It now reports the error. `Environment` updates also report API errors, which were previously ignored. [#1204](https://github.com/pulumi/pulumi-pulumiservice/issues/1204)
