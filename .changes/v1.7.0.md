## 1.7.0

### Improvements

- Added the `OrganizationMemberEntityAccess` resource, which grants one organization member a permission on one stack, environment or Insights account, for the [entity access](https://www.pulumi.com/docs/administration/concepts/rbac/entities/) feature. Name the member and the entity, and set `permission` to a built-in permission set such as `stack-write`, or `permissionSetId` to a custom one. Each resource manages one member's grant on one entity and leaves other grants untouched, including the grants of the same member on other entities.
- Added `reader`, `builder` and `maintainer` as values of `OrganizationMember.role`, and as roles reported by `getOrganizationMember` and `getOrganizationMembers`. They exist only in organizations that use the stored default roles, and Pulumi Cloud rejects them elsewhere. The provider resolves each to the organization's role ID, because the member API does not accept them by name. `getOrganizationMember` and `getOrganizationMembers` now report members on these roles with `role` instead of `roleId`.
- Added the `OrganizationDefaultRole` resource, which sets the default role of an organization: the role that members without an explicit role follow. It takes a built-in role in `role` (`reader`, `builder` or `maintainer`) or a custom role in `roleId`. Pulumi Cloud cannot clear the default role, so destroying the resource leaves the current default in place.

### Bug Fixes

- `OrganizationMember` with `role: member` now follows the organization's default role, the way members added in the console do, instead of being pinned to the default role's ID. `pulumi refresh` no longer reports a diff for these members, and a member listing without a fine-grained role keeps the declared `role` or `roleId`. [#1317](https://github.com/pulumi/pulumi-pulumiservice/pull/1317), [#1318](https://github.com/pulumi/pulumi-pulumiservice/pull/1318)
